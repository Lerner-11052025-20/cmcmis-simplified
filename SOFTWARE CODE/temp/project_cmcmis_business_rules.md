**This is the contract.** Every API endpoint and DB constraint must enforce these. User has explicitly authored these rules.

## BR-AUTH (Authentication & Identity)

| ID | Rule |
|---|---|
| BR-AUTH-01 | Login is by `employee_id` only (not email/username). Validated against existing employee table. |
| BR-AUTH-02 | User must exist in org's employee directory to log in. NO self-registration. |
| BR-AUTH-03 | Authenticated user with no role assigned → defaults to Normal User. |
| BR-AUTH-04 | Sessions expire after **60 minutes of inactivity**. Refresh token valid 7 days. |
| BR-AUTH-05 | First Super Admin seeded via DB migration using `SUPER_ADMIN_EMPLOYEE_IDS` env var (comma-separated). **Seed at least 2.** |
| BR-AUTH-06 | All login attempts (success + failure) are logged. |
| BR-AUTH-07 | Deactivated user (status = INACTIVE) cannot log in but history preserved. |

## BR-RBAC (Authorization)

| ID | Rule |
|---|---|
| BR-RBAC-01 | Only Super Admin can assign/change a user's role. |
| BR-RBAC-02 | **A user has exactly ONE primary role at a time** (no multi-role in v1). |
| BR-RBAC-03 | Permissions derived: User → Role → Permissions. NEVER check by role name in code. |
| BR-RBAC-04 | Sidebar items + routes filtered by permissions, not role names. |
| BR-RBAC-05 | Every API endpoint enforces permission check at controller layer. |
| BR-RBAC-06 | View-Only users can READ but cannot trigger any write op. |
| BR-RBAC-07 | Role changes take effect on next login OR token refresh. |

## BR-EQP (Equipment)

| ID | Rule |
|---|---|
| BR-EQP-01 | Every equipment has a unique serial number system-wide. |
| BR-EQP-02 | Equipment must belong to T&ME OR F&PE category. |
| BR-EQP-03 | F&PE may have NO calibration frequency (optional). |
| BR-EQP-04 | T&ME MUST have calibration frequency (in months). |
| BR-EQP-05 | `next_cal_due_date = last_cal_date + calibration_frequency_months` — computed on every cal record. |
| BR-EQP-06 | Equipment status transitions follow the state machine. |
| BR-EQP-07 | Hard DELETE = Super Admin only. CONDEMN (status flip) = Lab In-charge OR Super Admin. |
| BR-EQP-08 | Equipment search = case-insensitive across serial, model, manufacturer, type. |
| BR-EQP-09 | **NEW.** Every registration carries `registered_by` + `registered_at` + `verified_by` (nullable) + `verified_at`. |
| BR-EQP-10 | **NEW.** New equipment defaults to `PENDING_VERIFICATION`. Only Lab In-charge OR Super Admin can verify → `ACTIVE`. |

## BR-JR (Job Requests)

| ID | Rule |
|---|---|
| BR-JR-01 | Job request must reference existing equipment (or trigger registration). |
| BR-JR-02 | Job type ∈ {Calibration, Repair, Registration}. |
| BR-JR-03 | User can save as DRAFT before submitting. |
| BR-JR-04 | Once SUBMITTED, only Lab In-charge can change state. |
| BR-JR-05 | Submitted request must be assigned to a Lab Engineer before becoming a Job Card. |
| BR-JR-06 | "submitted by" auto-filled from current user — NOT overridable. |
| BR-JR-07 | High-priority repair requests appear at top of Lab In-charge's queue. |
| BR-JR-08 | Rejection requires mandatory reason (free text + reason code). |

## BR-JC (Job Cards)

| ID | Rule |
|---|---|
| BR-JC-01 | Job card auto-created when request is approved + assigned. |
| BR-JC-02 | Lifecycle: ASSIGNED → IN-PROGRESS → COMPLETED → VERIFIED/CLOSED. |
| BR-JC-03 | Only assigned engineer can mark IN-PROGRESS or COMPLETED. |
| BR-JC-04 | Only Lab In-charge can verify/close. |
| BR-JC-05 | Closed job can only be REOPENED by Lab In-charge with reason. |
| BR-JC-06 | Tasks are configurable per job type. |
| BR-JC-07 | Calibration cards REQUIRE: before-reading, after-reading, environmental conditions before COMPLETED. |
| BR-JC-08 | Job card history is **append-only** — immutable state transition log. |

## BR-PDF

| ID | Rule |
|---|---|
| BR-PDF-01 | PDFs generated on demand from current DB state. **Nothing stored.** |
| BR-PDF-02 | Job card PDF: header, equipment info, tasks, observations, signatures (textual), date. |
| BR-PDF-03 | Calibration cert PDF: equipment, standards used, readings, environment, uncertainty placeholders, valid-until date. |
| BR-PDF-04 | All PDFs include generation timestamp + "Generated by CMCMIS" footer + record ID. |

## BR-AUD (Audit & Security)

| ID | Rule |
|---|---|
| BR-AUD-01 | Every write op on critical tables logged in `audit_logs`. |
| BR-AUD-02 | Audit log captures: who, what, when, before-value, after-value, IP, user-agent. |
| BR-AUD-03 | Exports (PDF, future Excel) logged with user + record IDs. |
| BR-AUD-04 | Sensitive fields filtered from API responses based on permission. |
| BR-AUD-05 | HTTPS in prod. JWT in Authorization header. Refresh in httpOnly cookie. |

## BR-VIS (Row-Level Visibility)

| ID | Rule |
|---|---|
| BR-VIS-01 | Normal User sees ONLY their own job requests. |
| BR-VIS-02 | Lab Engineer sees jobs assigned to them + the queue. |
| BR-VIS-03 | Lab In-charge and above see ALL jobs and equipment. |
| BR-VIS-04 | View-Only User sees ALL data, performs NO actions. |

## BR-MASTER (Master Data — Phase 2 build, but rules locked now)

| ID | Rule |
|---|---|

## Functional Requirements (MVP) — FR catalogue

**FR-A (Auth & RBAC):** FR-A-01 to FR-A-10 — login screen, JWT issuance, logout, protected routes, sidebar permission filtering, Super Admin user mgmt (list/assign/activate-deactivate), GET /me endpoint, refresh-token endpoint.

**FR-E (Equipment):** FR-E-01 to FR-E-09 — list with pagination/search/filter, detail page, register (all roles except View-Only), edit, color-coded cal-due, history timeline, search by serial/model/mfr, soft-delete via CONDEMNED, **FR-E-09 (NEW)** Lab In-charge / Super Admin verify PENDING → ACTIVE.

**FR-JR (Job Requests):** FR-JR-01 to FR-JR-08 — list with filters, multi-section form, save as draft, submit, detail w/ state history, approve/reject with reason, approval auto-creates job card, assignment dropdown shows engineer workload (SHOULD).

**FR-JC (Job Cards):** FR-JC-01 to FR-JC-08 — list, status stepper, configurable task checklist, observations log, engineer state transitions, Lab In-charge verify/close/reopen, PDF generation, state history timeline.

**FR-D (Dashboard):** FR-D-01 to FR-D-06 — role-aware KPIs, cal-due alerts, engineer workload chart, equipment status pie, recently-updated jobs, permission-gated quick actions.

**FR-I (Inquiry):** FR-I-01 to FR-I-04 — 4-tab interface (Vendor/Product/Job Card/Instrument), debounced real-time search, drill-down links, empty-state messages.

**Note:** All "Admin module" master-data FRs are **moved to Phase 2 backlog**; when built, gated to Super Admin only.

**Why:** User explicitly authored this contract. These are non-negotiable rules + measurable targets.

**How to apply:**
- Every API endpoint must trace back to an FR + permission + relevant BRs.
- Every DB schema decision must satisfy at least one BR.
- NFR targets are measurable — write tests / observability against them.
- Session = 60 min inactivity (sliding) + JWT access 15 min + Refresh max 7 days. These coexist: short-lived JWT forces refresh; refresh denied if inactive > 60 min; refresh denied absolutely after 7 days.
- BR-RBAC-02 single-role simplifies schema: `users` table can have a single `role_id` FK (still keep `user_roles` join table for future multi-role flexibility, but enforce uniqueness).
- BR-EQP-10 adds new state: equipment lifecycle now starts at `PENDING_VERIFICATION` → ACTIVE (rest of lifecycle as before).
