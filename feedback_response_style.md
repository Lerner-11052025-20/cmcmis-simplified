**Rule:** From now on, ALL non-trivial responses must follow this structured style:

- Step-by-step format using memory-based descriptions
- Table-wise explanations wherever comparisons or matrices exist
- Flowcharts (ASCII or mermaid-style boxes/arrows) for processes
- Diagrams for architecture / design / data flow
- Relationships between concepts spelled out explicitly
- Simple explanation FIRST, then deep technical detail
- Real-world examples to anchor abstract ideas
- Module connections shown visually
- Summarized notes ("Quick Recap" / "Key Takeaways") at the end
- Visually organized, easy to revise, beginner-to-advanced friendly

**Why:** User explicitly demanded this style ("From now on, explain everything in a structured step-by-step format...") and reiterated "as always now onwards" — he revises responses later as study/reference material, so visual structure is load-bearing for him.

**How to apply:**
- For complex/technical asks: use full structure (sections, tables, ASCII diagrams, examples, recap).
- For trivial asks (one-line questions, quick code fixes): keep it short but still readable — don't fake structure where there's nothing to structure.
- Default to MORE structure rather than less when in doubt.
- Use headers, bold labels, and consistent formatting; emojis only where they aid scanning (sparingly).
- Always close longer responses with a "Quick Recap" block.

See [[user-role]] — he is a learner shipping his first industry-grade project, so this style supports both his work AND his learning.
